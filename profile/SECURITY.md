# Security Policy

The `arschaos` team takes the security of our software, defensive tooling, and infrastructure projects very seriously. We appreciate the efforts of security researchers and community members who help us keep our codebases safe.

---

## ⚠️ Reporting a Vulnerability

**Please do NOT report security vulnerabilities through public GitHub issues, pull requests, or discussions.**

If you believe you have found a security vulnerability in any `arschaos` repository or tool, please report it privately:

1. Go to the **Security** tab of the affected repository.
2. Select **Advisories** from the left sidebar.
3. Click **Report a vulnerability** to open a private report with the maintainers.

### What to Include in Your Report
To help us triage and respond faster, please include:
- A description of the vulnerability and its potential impact.
- Step-by-step instructions (or a minimal Proof of Concept) to reproduce the issue.
- The specific repository, version, binary, or commit hash affected.

---

## ⏱️ Response & Disclosure Timeline

When you report an issue privately, you can expect:

| Stage | Timeline |
| :--- | :--- |
| **Initial Acknowledgment** | Within **48 hours** |
| **Triage & Severity Assessment** | Within **5 business days** |
| **Patch & Release Plan** | Dependent on severity; regular updates provided every 7 days |

We request that you give us reasonable time to fix and release a patch before disclosing the vulnerability publicly.

---

## 🛡️ Scope & Safe Harbor

We consider activities conducted in good faith under this policy to be authorized. We will not pursue legal action or issue access bans for research that:
- Refrains from compromising user data, executing destructive attacks, or overloading infrastructure.
- Avoids social engineering, phishing, or physical attacks.
- Complies with local laws and gives reasonable time for remediation.
